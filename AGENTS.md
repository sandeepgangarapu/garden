# Garden app conventions

- Plain HTML/CSS/ES2020 modules, no build step or frameworks. Mobile first, 600 px max column. Preserve paper/green tokens, system serif headings, light mode only (no dark theme, by request), safe areas, 16 px inputs, and ≥44 px touch targets.
- `data/plants.json` and `data/guides.json` are authoritative. `scripts/build_library.py` is a one-time migration; rerunning overwrites edits. Plant fields and job fields follow neighboring records. Timelines have 12 codes, months are zero-based; all data is plain text, escaped when rendered.
- Never rename shipped plant IDs or task IDs. Notes/checkmarks refer to them. Custom IDs start `custom-`. Scope general jobs with `area:front`, `area:back`, `area:vegetables`, or `area:ornamental`.
- A plantings row is either `planned` or `skipped` (older rows may hold other statuses; treat anything but `skipped` as planned). Notes are dictated per year without a plant or kind: new notes use `plant_id: 'garden'` and `tag: 'note'` because the API still requires both. A plant's notes are those filed under it or naming it; plant names in notes, jobs, care and guides render as links (`plantMatcher` in `logic.js`).
- Keep pure rules in `logic.js`; persistence/sync in `store.js`. Guard every localStorage access. Preserve serialized sync, normalized ISO timestamp conflict resolution, persisted dirty keys, in-flight edits, and soft deletes on every table. First-run seeds use epoch timestamps and are never dirty. No prototype notes or client credentials.
- Keep `classic/` unchanged (archived old page). The idempotent D1 schema is `worker/schema.sql`; include owner in every key. The service worker is network-first; cache only the app’s own assets.
- Sync batches are capped at 40 changes (`SYNC_BATCH` in store.js, `MAX_CHANGES` in worker/api.js) because D1's free plan allows 50 queries per request. Keep both in step.
- Access email PIN is the only sign-in. Production verifies Access JWTs in `worker/access.js`; `worker/api.js` contains no auth. The test entry trusts `X-Test-Email`, must stay isolated, and must never be imported by production. Browser requests are same-origin only; never intercept `/api/` or `/cdn-cgi/` in the service worker. Deploy only when asked: pushing to `main` publishes the static site; `scripts/deploy_worker.py` publishes the Worker (see README).
- Test: `python3 -m http.server 8787`, open `/tests/`, or dump its DOM with headless Chrome. Inspect all tabs and plant/picker sheets at 390×844 (also with the device in dark mode, to confirm it stays light), and widths 320–430 px. Check sign-out/offline behavior and storage failures. Avoid tests that only mirror implementation.
- Always use `uv` for Python packages, environments, and dependency workflows. No Python packages are needed today.
